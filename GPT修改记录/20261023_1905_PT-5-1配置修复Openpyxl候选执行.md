# 2026-10-23 PT-5-1 配置修复 Openpyxl 候选执行

## 本轮目标

将 PyTools 配置修复（PT-5-1）从计划语义对拍推进到真实 Rust CLI 的能力门控候选执行。仅使用临时测试 capability；不登记生产能力，不改变 ExcelModifier 默认路由，不修改只读 Python 源项目。

## 修改文件

- `pytools-core/src/config_admin.rs`：计划只声明当前 validator 可验证的保留项；将示例空字符串写为 `CellValue::Blank`，匹配 openpyxl 保存后的 XLSX 空单元格语义。
- `crates/excel-editor/src/openpyxl_backend.rs`：当要求保留样式时执行 umya readback；对计划删除的源工作表跳过未修改样式检查，避免把合法删除误报为样式损坏。
- `pytools-core/tests/config_repair_execution.rs`：新增 Unix/隔离 runtime 集成测试，通过 CLI、临时精确 capability、ExcelModifier 和 openpyxl worker 批量修复合成配置簿，并检查配置、工作表顺序、注释、样式、合并、行列尺寸及源文件不变。
- `pytools-core/probe/compare_config_repair_plan.py`：扩展 Python/Rust 对拍，运行 Rust openpyxl 候选执行并比较合成配置及只读真实配置簿副本的工作表、值和批注投影。
- `pytools-core/MIGRATION_INVENTORY.md`：记录 PT-5-1 候选执行范围、数据流、证据与尚未通过的生产验收项。
- `pytools-core/probe/reports/config_repair_execution_20261023.json`：记录机器可读结果。
