## 能力、限制与未执行项

- OpenpyxlWorker 已进入 ExcelModifier 的候选路由和 pytools dispatcher；只接受 XLSX，能力由传入的精确 Passed capability 门控。没有创建 production capability JSON，没有改任何生产默认路由。
- 当前 synthetic 测试验证了普通值/公式文本、批注文本及位置保留、sheet 身份顺序、合并区域、填充、行列尺寸、页面设置、CopyRange/ImportRange 等首批操作。Rust 独立读回会验证 ImportRange/CopyRange 的样式语义、设定的行高/列宽、填充色、日期格式与页面设置；打印区域从输出包 `workbook.xml` 用 namespace-aware parser 读回。它不证明真实模板保真或打印渲染一致。
- ImportRange 的行高/列宽/隐藏/outline 复制标志在 Rust adapter 写前拒绝，直到补齐这些属性的独立 Rust 读回验证；worker 内部虽实现相关操作，不能据此开放路由能力。
- 不支持行/列插删；不支持非 XLSX；拒绝未知 OOXML 部件、带非空公式缓存的输入及未验证复杂公式对象。数组/数据表公式复制无支持保证。Excelize 仍是占位，未实现 Go worker。
- 没有收到两个原始项目的脱敏真实模板。本轮未产生真实样本对拍，不声称 Audit 或 pytools 的任何 openpyxl 能力已完成生产验收。当前 Audit 没有接入此 backend 的业务调用链；pytools 只有通用 capability dispatcher 注册，没有新增业务操作。
- packaging staging 脚本只接受已准备好的可重定位 Python runtime；本轮开发环境使用 Python 3.12.3/openpyxl 3.1.5。尚未构建目标 Python 3.8.10 runtime、deb，也未在麒麟 V10、统信 V20 或 glibc 2.28/2.31 验证。
- 公式计算、审核/统计业务、读取、新建 XLSX 不由 worker 承担；两个源 Python 项目没有修改。
