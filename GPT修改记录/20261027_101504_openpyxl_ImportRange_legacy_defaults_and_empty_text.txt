## 目的

让隔离 openpyxl worker 与 Rust readback validator 一致复现旧 Python ImportRange 的字段级样式语义，并只对 openpyxl 保存时确实发生的非公式空字符串归一放行。此项来自 Audit S1-F01 真实对拍暴露的问题；不改变生产路由，不代表 Audit S1-F01 已验收。

## 变更

- `crates/excel-editor/python/openpyxl_worker.py`：有直接 cell style 时复制相应直接样式组件；无直接样式时仍按旧 Python 的真值判断应用默认 number format、alignment（Full 模式另含 protection），同时保留目标格的 font/fill/border 等未被旧路径覆盖的组件。
- `crates/excel-editor/src/openpyxl_backend.rs`：计算 ImportRange 预期样式时从原目标工作簿初始化目标样式，再按操作顺序叠加源字段；无样式源格的默认属性不会错误覆盖目标的其他直接样式组件。未修改能力路由或 API。
- `crates/excel-editor/src/openpyxl_backend.rs`：工作簿保护校验仅接受非公式空文本保存后变为空白；不放行空格文本丢失或公式/缓存丢失。
- `crates/excel-editor/tests/python/test_openpyxl_worker.py`：新增空 inline string 经 openpyxl 保存后归一为空白的回归。
- `crates/excel-editor/src/openpyxl_backend.rs`：增加无直接样式源格、目标已有格式，以及空字符串归一的 Rust 回归覆盖。
- 不改业务代码、依赖、配置、公共路由、其他产品工作树或 Excel-Core 生产默认。
