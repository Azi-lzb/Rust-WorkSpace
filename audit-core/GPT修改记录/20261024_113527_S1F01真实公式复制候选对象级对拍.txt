## 实际数据流与候选结果

- Python 默认映射从模板解析 4 个复制范围；模板有 1,072 个公式单元格和 8 个结构区域。样本子批次共 68 个可发现工作簿，Python 结构预检接受 17 个，本轮按既有候选范围取 7 个逐本测试。
- Rust 对每本目标以 direct、Unverified `UmyaXlsxBackend` 执行 4 个 `ImportRange` 和计算属性操作；不进入生产 CLI、不重算公式、不修改输入。7/7 目标包 inventory 完整并生成临时候选；7/7 输入前后保持不变。
- 对拍 5,487 个复制区域单元格：值/类型、公式文本、批注位置/文本/作者、超链接差异均为 0。复制样式对照模板后，样本 1 有 100 个样式差异，样本 2–7 各有 802 个。
- 未修改区每本对比 3,047 格：值/类型差异分别为 216、211、207、211、219、209、223；公式、样式、批注、超链接差异均为 0。Python/Rust 与原目标/Rust 工作簿元数据差异均为 0。
- 每本 Python/Rust ZIP 输出观察到 17 个部件名差异（comments=8、drawings=8、other=1）和 19 个共同部件字节差异（Content_Types=1、other=4、relationships=2、styles=1、workbook=1、worksheets=10）。这些是序列化层观察，未单独推断为对象损坏；具体对象安全按上面的值/样式/批注/链接及元数据比较。
- 旧 Python 输出的 style table 有无效 font component references（首个样本 1,012 个；源模板与目标为 0），导致旧 comparer 在 `openpyxl` 访问 copied-range font 时触发 `IndexError`。本轮不以该 Python 输出的复制区样式作为正确值；样式依据模板，Python 的缺陷单独报告。改进后的 comparer 完成 7/7 对拍，无 readback exception。
- 候选存在真实的复制区样式差异和未修改区值/类型变化，因此能力维持 Unverified，生产路由资格为 false。以上证据见 `audit-core/probe/reports/s1_formula_copy_candidate_real_batch.json`。
