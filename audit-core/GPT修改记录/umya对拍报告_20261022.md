# umya-spreadsheet 精细修改对拍报告

日期：2026-10-22  
项目分支：`rust-migration`  
探针依赖：[umya-spreadsheet 3.1.1](https://docs.rs/crate/umya-spreadsheet/3.1.1)

## 范围与环境

本次检查新项目骨架，不迁移业务代码。公开仓库与旧项目可用资料中没有找到可放入本项目的脱敏真实工作簿；因此仅使用 `tests/fixtures/synthetic_probe.xlsx`，该文件由 `tests/compare/make_synthetic_fixture.py` 生成，数据为合成值。真实模板数量为 **0**，本报告不代表生产模板验收。所有修改输出写到系统临时目录，未覆盖 fixture。

- Windows 11 x86_64，Python 3.12.10，OpenPyXL 3.1.5；OpenPyXL 仅用于独立结构对拍。
- WSL Ubuntu 24.04 x86_64，glibc 2.39，Rust/Cargo 1.99.1；工作簿由 Rust 探针处理。
- 合成样本：1 个工作簿、1 个 sheet、合并单元格、条件格式及 dxf、数据验证、批注、defined name、公式、冻结窗格、筛选器和打印设置；另生成 56 个值供随机未改动单元格抽样。
- 未使用 Excel、WPS 或 LibreOffice；公式只检查文本，没有重算。

## 修改操作结果

`umya-probe` 对清单中的 10 类修改均执行成功：普通单元格值、合并锚点值、字体/填充/边框/数字格式、公式文本、defined name 目标值、条件格式区域值、数据验证区域值、批注单元格值且批注文本保持、行高/列宽/隐藏行、打印区域。探针也能读取本样本中的条件格式与数据验证集合；这不等于对其他模板对象组合完成验收。

| 输出 | 结果 | 说明 |
|---|---:|---|
| umya 原始保存 | 17/18，94.44% | 文件可由 OpenPyXL 打开；合并、条件格式+dxf、验证、批注、名称、行尺寸、冻结、筛选、打印、公式、目标修改、样式及 50 个抽样单元格均通过。唯一失败是未请求修改的列尺寸集合。 |
| 原始保存的列尺寸差异 | 失败 1 项 | umya 输出为 A:H 显式宽度 8.38 及 I=25；源文件没有 A:H 的显式 `<col>` 定义。该差异会改变模板列尺寸的显式表示。 |
| 列定义定点补丁后 | 18/18，100% | namespace-aware 解析并恢复源 `<cols>` 定义，只应用请求的 I=25；未用正则替换 XML 全文。 |
| 补丁范围 | 3/3，100% | zip 部件数仍为 13；仅 `xl/worksheets/sheet1.xml` 发生变化；变化限定在 `<cols>`，其他 12 个部件保持不变。 |

具体逐项结果和差异保存在临时 JSON：`%TEMP%/open-data-audit-rust-probes/reports/umya_raw_compare.json`、`umya_patched_compare.json`、`patch_scope.json`。随机抽样固定种子 `20261022`，共检查 50 个未修改单元格。

## 结论与决策

原始 umya 结果达到规则中的 90% 门槛，但暴露出一个确定、范围狭窄的列定义保留问题。为避免把该项失败隐藏在整体比例中，当前候选编辑路径为 **umya 修改 + 仅针对列定义的 namespace-aware OOXML 补丁**。本合成样本的补丁结果通过 18/18 检查，补丁范围通过 3/3 检查。

目前不启用 Go excelize：本样本没有出现大面积保留失败，且失败项已有窄范围补丁。该结论仅适用于本合成样本；真实脱敏模板尚未提供，故 umya 不进入生产默认候选，真实对象组合必须逐模板补验。遇到图表、透视表、ActiveX、嵌入对象、外部链接、VBA 或未验证 drawing 时，探针按设计拒绝处理，不推断支持。
