## 目的与实现

将已迁移的条件格式审核、公式结果提取和历史归类接入单一 Rust CLI 链路：

- 新增 `open-data-audit s1-audit-directory`。它发现或筛选源 XLSX，加载模板规则和命名区域，先做表结构预检，再从显式清单读取已保存公式结果副本；清单必须精确覆盖所有通过预检的源文件。
- 公式 Issue 与条件格式 Issue 按源文件合流，每个文件先公式、后条件格式；条件格式 Issue 的 `audit_file` 指向对应公式审核副本；随后调用现有 Rust 历史分类。
- 普通视图与开发者视图记录执行步骤、实际引擎和耗时。该入口不复制公式、不重算公式、不修改或输出审核工作簿。
- 新增真实样本 Python/Rust 对拍工具和合成 CLI 夹具/测试。真实对拍不保存路径或 Issue 内容；因真实源文件名超出 Linux 路径组件限制，本次临时副本以 ASCII 文件名运行，机构身份解析不覆盖原始长文件名。

## Python 业务口径差异

真实样本共有 146 条公式 Issue、2 条条件格式 Issue、602 个条件格式评估单元格。与 Python `workflow.adapters.audit_handlers.handle_conditional_issue_extract` 的 Windows/general 路径比较时，148 条当前 Issue 和合并历史的全部字段差异均为 0；源文件、审核副本和模板均未变化。汇总见 `audit-core/probe/reports/s1_issue_chain_real.json`。

源 Python UOS/native 路径使用 `workflow.adapters.native_audit_handlers.handle_conditional_issue_extract`，该处理器没有传入 `org_code` / `org_name`；Windows/general 处理器传入源文件机构信息。Rust 当前沿用机构信息，因而与 UOS/native 路径在两条条件格式 Issue 的机构字段上不同。迁移目标为 Linux，按 `audit-core/AGENTS.md` 的业务语义冲突要求，先记录并等待用户指定基线；S1-F01 总体仍为“未验证”。
