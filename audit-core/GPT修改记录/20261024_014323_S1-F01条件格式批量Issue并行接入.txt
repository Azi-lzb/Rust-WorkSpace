## 目的与改动

将 Python `handle_conditional_issue_extract` 的选中文件批处理行为继续接入 Rust S1 条件格式 Issue 阶段：按文件并行求值、保留清单顺序与每文件机构信息，全部输入成功后才返回合并 Issue。`conditional-audit-batch` CLI 接受 JSON manifest，输出 Issue JSON，并为普通用户和开发者视图记录实际 reader、文件状态与阶段耗时。单文件 CLI 普通日志也补充 reader 和读/判定/组装耗时。

批处理失败时命令以错误退出，不输出部分 Issue 汇总；公式仍读取工作簿已有缓存，不重算或写回输入文件。此变更只覆盖条件格式 Issue 提取，不代表完整 S1-F01。

修改/新增文件：

- `Cargo.lock`、`audit-core/Cargo.toml`：Audit crate 登记已由 workspace 声明的 Rayon 依赖；锁文件仅增加 `audit-core` 的 Rayon 依赖项。该需求已向 main 报告并完成依赖边界核对，不修改共享 crate。
- `audit-core/src/s1_conditional_audit.rs`：增加批处理输入、逐文件进度/摘要和 Rayon 文件级并行 API。
- `audit-core/src/bin/open-data-audit.rs`：增加 `conditional-audit-batch` manifest CLI 与双视图日志。
- `audit-core/tests/s1_conditional_audit_batch_cli.rs`：覆盖两文件合并、机构元数据/顺序、reader/计时日志和错误时不输出部分结果。
- `audit-core/tests/s1_conditional_audit_cli.rs`：断言单文件普通日志包含引擎与读取阶段。
- `audit-core/README.md`、`audit-core/MIGRATION_INVENTORY.md`：记录入口、并行和当前未迁移范围。
