# 技术实现参考（旧实现背景与迁移提示）

> 本文件迁移自旧 Python 产品。下方旧实现细节仅用于发现业务行为，不能作为 Rust workspace 的生产技术指引；当前技术边界见根 `AGENTS.md` 和规则 13。旧 UI 专项只有在对应产品 UI 纳入迁移范围后才适用。

## 汇总核查平台差异

| 操作 | Rust 主路径 | 可选 sidecar / 边界 |
|---|---|---|
| 条件格式规则读取/求值 | Rust/OOXML 仅实现并验收明确需要的静态规则 | 不支持渲染或 PDF 导出 |
| 公式文本复制/写入 | 已验收的 ExcelModifier 引擎处理完整修改计划 | 不启动 Office；重算须另行显式触发 sidecar |
| 工作簿重算 | 主路径默认不重算 | 用户显式触发时由独立 sidecar/lo-convert 调用已安装的 LO/COM |
| 重算后缓存读取 | Rust reader 校验缓存及公式文本 | Python 仅用于对拍基线 |

公式复制/计算要求：

- 旧 Windows COM 实现是行为参考，不能进入主路径；公式文本操作走 ExcelModifier，并以 Snapshot/对拍确保公式内容。
- 主路径先以 Rust 写入/保留公式文本。只有显式触发重算时才调用 sidecar；无外部引擎或缓存未刷新时明确失败，不能使用旧缓存结果冒充本轮结果。
- 组合工作表仅处理结构和值，不调用公式计算引擎。

## 性能记录清单

性能优化按 `rules/07_测试与发布.md` 报告，并根据场景记录：

- 输入工作簿/工作表/区域/公式数量与文件大小；
- Snapshot、打开、复制、计算、保存、关闭等关键阶段耗时及冷/热启动差异；
- 输出文件差异、公式错误、条件格式/批注/命名区域/外链保留情况；
- 原始文件 SHA-256，以及 Windows/UOS 结果差异（涉及双平台时）。

## UI 颜色体系（旧 Python UI 参考；core/frontend/web/index.html）

两套模式共用一组 CSS 变量：日间完整定义于 `:root`，夜间由 `body.dark` 全量覆盖
（夜间不含纯黑变体，`body.black` 规则已随三主题移除）。
所有组件样式一律引用变量；新增颜色时必须先进变量再引用，禁止在规则里写死色值。

> 以下 CSS、settings.py、web_app.py 路径描述旧 UI。只有未来 UI 迁移明确保留这些交互时才应用；不得因此引入 Python 运行时。

### 基础变量（调整某一颜色改对应主题块的值即可）

| 分组 | 变量 | 用途 |
|---|---|---|
| 结构 | `--bg` `--surface` `--surface-2` `--border` `--border-strong` `--sidebar` | 页面底、卡片、次表面、边框、侧导航 |
| 文字 | `--text` `--text-2` `--text-3` | 主/次/弱三级文字 |
| 主色 | `--accent` `--accent-hover` `--accent-soft` `--accent-ring` | 按钮、链接、选中态、标题、焦点圈 |
| 主色派生 | `--accent-soft-hover` `--accent-border` `--accent-border-strong` `--accent-glow` `--accent-line` | 淡底 hover、soft/guide 边框、强边框、primary 投影、链接下划线 |
| 语义 | `--success` `--success-soft` `--success-border`（warn/danger 同构，danger 另有 `--danger-soft-hover` `--danger-border-hover`） | 成功/警告/危险及配套边框 |
| 控件 | `--btn` `--btn-hover` | 普通按钮底色 |
| 固定 | `--console-bg/text/border` `--overlay` `--shadow-card` | 日志控制台（全主题深底）、弹窗遮罩、卡片阴影 |
| 非颜色 | `--radius` `--radius-sm` `--font-display` | 圆角、衬线标题字体 |

### 换主色指引

只改两处共 5 个变量，全站自动跟随：
`:root` 与 `body.dark` 中的 `--accent` `--accent-hover` `--accent-soft` `--accent-ring`
（如需连动投影再加 `--accent-glow`）。深浅两套主色需分别保证与各自 `--surface` 的对比度；
深墨蓝一类深色不能直接用作深色主题主色（对比度不足）。

### 界面模式与主题色预设（设置中心"背景"分组）

界面模式三档：日间（默认，纸张背景）/ 日间纯白（纯白背景，body.day-white 只覆盖
--bg 与 --sidebar，层次靠边框）/ 夜间，存 `ui_theme`（`UI_THEMES` 白名单）；旧值
浅色/深色/纯黑经 `LEGACY_UI_THEME_MAP` 迁移（浅色→日间，深色/纯黑→夜间）。

主题色 8 个（默认蓝/青/绿/紫/金/橙/玫/靛），存 `ui_accent`（`UI_ACCENTS` 白名单）。前端
`ACCENT_PALETTES` 按"颜色名 × 日/夜变体"组织：**两组色板的键名必须完全一致**，
`applyAccent()` 按当前模式取同名变体覆盖 9 个 accent 系变量，模式切换自动换浓淡；
若两组键名不一致，回退链会落到错误色板（曾在夜间退化为日间默认蓝）。
**注入层级陷阱**：accent 变量必须同时注入 `html` 与 `body` 的内联样式——夜间模式的
`body.dark{}` 在 body 上定义了同名变量，只注入 html 时继承值会被 body 规则覆盖，
表现为"夜间模式主题色无法切换"（日间正常）。验证主题色必须读元素的实际渲染色
（computed backgroundColor），只读 `documentElement` 上的变量值会被假象欺骗。切换立即生效
并随 state→settings 回写持久化。新增预设须同时补 settings.py 白名单与前端两组色板；
新增设置项后须检查 web_app.py 的 state 初始化、update 分支与 state→settings 回写三处齐全。

### 保留硬编码的例外

- 白字 `#fff`（primary/primary-hover 按钮文字等）：彩色底上恒定，不随主题变化；
- 模块图标四组色（暗金/蓝灰/苔绿/紫，含 `body.dark` 覆盖）：组件级固定色，调整时单独改；
- 阴影与进度条 shimmer 中的 rgba 黑白值、状态圆点 `#a6b3c2`：中性色；
- 日志控制台三色已变量化（`--console-*`），但三主题共用同一深底。

### 高级设置双布局

"高级设置"页签支持双击切换"按系统分类"（运行时环境/通用设置/逐笔统计系统/大集中统计系统，
默认）与"按功能分类"（本机运行环境/文件选择/Excel 文件处理/计算与条件格式/大集中表达式求值），
选择存 localStorage `advLayout`。设置行按归属定义一次，两套布局各自组装；新增设置项需同时
声明其两种布局下的分组归属（或仅属于其一，见 renderAdvanced 内 rows* 数组与 cards 组装）。
