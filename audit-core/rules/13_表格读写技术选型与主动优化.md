# 表格文件读取、写入与修改技术选型规范（Rust+Go 迁移项目）

> Workspace 通用 Excel 技术规范现已集中于 [根规则 13](../../rules/13_Rust_Excel读写修改与引擎路由规范.md)。本文件继续保留 Open-Data-Audit 业务操作映射和历史约束；冲突时遵循根 AGENTS.md 与根规则 13，不覆盖业务基线。

> 文档版本：1.2-RustGo.2（规则版本，不是产品版本）  
> 更新日期：2026-10-23  
> 适用目标：麒麟 V10 x86_64（glibc 2.31）与统信 V20 x86_64（glibc 2.28）；离线 deb 自包含，不安装 Office、WPS 或 LibreOffice。  
> 覆盖说明：openpyxl 不进入 reader/writer/业务计算路径；它仅可通过 workspace 规则 13 限定的隔离 worker 作为可选 XLSX 修改引擎。Rust-owned 普通存储值 XLSX 在同契约时优先评估 Calamine，OOXML 专属元数据只由对应对象已验收的 namespace-aware 适配器读取；不设 Calamine 失败后的通用 Direct OOXML fallback。Rust-owned 纯数据新建 xlsx 优先评估 rust_xlsxwriter，但须通过输出契约和功能级内存预算。性能证据的环境、范围及无默认路由变更要求以 workspace 根规则 13 §6.2、§9.2 为准。既有工作簿修改由 ExcelEditPlan/ExcelModifier 按格式、对象特征和整批操作组合选择已验证的 OOXML Patch、umya-spreadsheet、Go Excelize worker 或 openpyxl worker；不预设 workspace 级默认编辑器。公式重算默认关闭，但允许显式调用独立 sidecar/lo-convert。源函数入口清单见 workspace 根目录 PYTHON_EXCEL_OPERATION_INVENTORY.md。

## 1. 执行原则

本文件中的“必须”“禁止”“默认”“不支持”是执行规则。技术选型按第 2～5 节执行；第 8 节规定本迁移项目的边界，不能充当具体后端的验收证明。

同一功能分别确定读取、业务计算、写入和格式转换方式；本 workspace 不提供渲染路径。旧 pandas 仅作为源项目实现信息或对拍基线，不得成为生产数据处理或 Excel 后端。

**确定性不等于承诺所有格式都能处理。能力不足时，确定结果就是“不支持当前要求”，并报告具体缺项。agents 不得用降级输出掩盖能力缺失。**

开发和维护还必须执行本节下方的主动效率检查流程。本规范与 [Excel/OOXML 边界](03_Excel与OOXML边界.md) 配合使用：本规范负责输入输出契约、操作匹配、可用后端选择与用户选项；03 负责文件结构硬边界；AGENTS.md 规定本迁移项目的执行顺序和边界。用户当前指令优先。

### 本项目技术分工（硬规则）

- **Rust 读取**：Rust 持有数据的普通存储值 XLSX，在坐标、类型、空值和值语义匹配 workspace 根规则 13 §6.2 的基准契约时优先评估 Calamine。其他格式/契约按具体能力验收；Calamine 失败不得以 Direct OOXML 通用 fallback 掩盖。Calamine 未提供且业务确需的 OOXML 专属元数据由对应对象已验收的 namespace-aware reader 补足；openpyxl 只在 `tests/compare/` 作基线。Python-owned 迁移期流程保留原项目同契约已验收路由，任何调整先测完整调用链。批量文件处理使用 Rayon 做文件级并行。
- **Rust 新建写入**：Rust 持有结果并从零生成纯数据 xlsx 时，优先评估 rust_xlsxwriter，只有输出契约通过且峰值内存符合该功能资源预算后才采用。旧项目中的 `s1-summary-writer`、`s3-comparison-writer`、`s5_result_writer` 名称仅用于识别源功能，不是 workspace 现有模块路径；新模块按实际迁移后的业务结构放在 `audit-core/`。新建 writer 不得打开并保存既有模板。
- **精细修改候选**：业务只生成 ExcelEditPlan，由 ExcelModifier 按完整操作批次路由给一个已验证引擎。OOXML Patch、umya-spreadsheet、Go Excelize 和隔离 openpyxl worker 都是候选；按真实保真度、性能、维护成本和失败行为决定启用范围，不根据语言或理论速度固定优先级。openpyxl worker 只可在内部绝对路径启动隔离 Python runtime，按 workbook 批量处理；不支持读取、新建报表、业务规则、行插删或公式重算。没有与 Audit 真实模板/操作组合/平台匹配的 capability 证据时，不得选择该 worker。
- **Go worker**：作为复杂 XLSX 修改候选/保底方案，经同一真实模板和操作组合对拍证明有收益后才纳入。一个 IPC 请求提交一份文件的完整计划，不逐单元格跨进程；CGO_ENABLED=0 静态编译，不要求用户安装 Go。
- **OOXML 边界**：维护 package relationships、Content_Types、sheet 身份/顺序、sharedStrings 和 defined names；每个适配器都要对拍其涉及的保留项。含未验证 drawing、图表、透视表、宏或其他对象时拒绝处理，不猜测、不硬扛。
- **公式计算**：默认只保留公式文本且不承诺本轮计算值；用户显式要求本轮结果时，可通过独立 sidecar/lo-convert 调用 LO/COM 重算并校验缓存已刷新。sidecar 缺失时报告“该功能需要外部引擎”，不得以旧缓存或静态值冒充重算。
- **验收纪律**：API 不存在写“跳过：API 不存在”；模板不含对象写“不适用”；未实际执行或计时写“未测量”；不得用概括性结论掩盖失败项。

已有功能保留已验收的默认路由；变更默认路由执行第 9 节的迁移条件。新功能使用第 4 节给出的默认顺序。阅读本规范本身不授权批量重写现有功能。

### 主动效率检查流程

1. 开发、修复或维护业务功能时，先识别业务功能、实际调用链及其配置来源；旧项目 Sx-Fxx/Sx-CFG-xx 编号仅在有助于来源映射时记录，不作为 workspace 版本编号。按第 2 节填写输入输出契约，并分别标出读取、规则计算、写入、公式文本处理和同类格式转换阶段；本 workspace 不包含渲染阶段。纯文档/样式任务只核对相关规则，不运行无关业务基准。
2. 检查本次功能的重复打开/保存、逐单元格 COM/UNO 调用、重复的大型中间集合构造；旧 Python DataFrame 路径仅供来源行为参考、无必要的格式转换、缓存失效、宽泛异常回退和对象保留缺口。只检查当前功能及直接依赖，不扩展为无授权的全系统重写。
3. 发现具体热点或能力缺口时，必须主动提出技术调整方案，列明当前入口、代码或阶段计时证据、替换阶段、候选后端、格式/平台/保留项、实施范围和验收指标。未测量写明“尚未测量”，先给出测量方法，不承诺提速倍数。
4. 新增性能敏感能力按本节技术分工评估 Rust；Direct OOXML writer 仅在已有验收证据时作为基线，不将任何候选未经对拍切为默认，也不把原有优化报告成新增成果。
5. 同一契约有多个合格后端时，按系统、功能和阶段提供默认“自动”与用户手动选择，持久化设置；未验收后端不进入选项。不得为了技术齐全给每个操作加入全部库。
6. 已授权的探针和必要修复完成实现与对应验收；业务迁移须在两份对拍报告完成并按决策规则记录后进行。超出授权的输出语义或外部依赖变化先形成可审阅方案。
7. 交付列出默认方案、用户备选、实际测量、已执行与未执行验收。未发现后端迁移依据时说明原因并完成原任务；不得编造提速建议。
8. 每次实际修改在 `GPT修改记录/` 新增记录，格式按 rules/08；纯规则变化不升级版本、不写入用户版更新日志。workspace 的 crate 版本按 Cargo 规则治理；旧产品 rules/11 的产品/组件版本制度未经另行确认不适用。


## 2. 先确定功能输入输出契约

agents 在实现前填写下表。已有需求、配置和代码能确定的项目直接填写；只有会改变结果且无法从上下文确定的信息才询问用户。

| 字段 | 取值和默认规则 |
|---|---|
| 操作 `operation` | 选取第 4 节的操作编号；一个功能含多个阶段时分别编号。例如“xls 时序提取并生成 xlsx”是 R01 + W01。 |
| 平台 `platform` | 记录发行版版本、CPU 架构、glibc ABI、Rust/Go 版本和目标三元组。跨平台功能分别填写各目标平台。 |
| 输入 `input_format` | 按文件实际内容识别；扩展名只用于初筛。识别不到或扩展名不匹配时停止，禁止靠改后缀处理。 |
| 输出 `output_format` | 新建工作簿默认 xlsx；修改已有文件默认保持原格式；格式转换使用用户指定格式。输出原格式不被 writer 支持时报告不支持。 |
| 输出形态 `output_kind` | `new_report` 新报表、`edit_existing` 修改已有工作簿、`format_convert` 格式转换、`page_setup` 写打印页面设置、`filesystem` 文件操作；PDF/render 不支持。禁止把重建报表当作修改既有工作簿。 |
| 值的口径 `value_view` | 默认 `stored`：读取文件中存储并解码的值；用户要求“显示出来的文字/金额/百分比/前导零”时选 `displayed`，执行 R04。数值 1 配格式 000 的显示值是 001，普通 str(1) 不满足该要求。 |
| 公式口径 `formula_mode` | 纯取值默认 `cached`：接受文件上次保存的结果，不承诺本轮重算；读取/保留公式文本选 `text`；同时取文本和缓存选 `text_and_cache`；要求按本轮输入计算选 `recalculate`。修改既有文件默认保留公式文本。 |
| 保留项 `preserve` | 新建纯数据报表默认保留字段、值、类型和任务指定的行列位置；不复制源版式。修改既有文件默认保留除本次变更对象以外的既有功能，先列出对象清单，再验证 writer 全部覆盖。转换默认保留目标格式能够表达的源对象；目标格式不能表达的对象执行冲突检查。 |
| 允许丢弃项 `drop_allowed` | 默认空集合。丢弃源格式不等于丢弃公式、宏、工作表或批注；每一项须由功能定义或用户明确允许。 |
| 中间转换 `allow_conversion` | 显式格式转换为 true；其他操作默认 false。读取 xls 的值不需要先转 xlsx；对 xls/xlsb 修改后输出 xlsx 必须在契约中明确该转换。 |
| 外部应用 external_apps | 默认禁止 Office/WPS/LibreOffice/COM/UNO；只有用户显式触发公式重算或同类格式转换时，才允许独立 sidecar 调用 LO/COM。
| 应用基准 `reference_app` | 默认 `none`。本项目不承诺与 Excel/WPS/LibreOffice 的专属计算或渲染语义一致；需要这些语义的操作判定不支持。 |
| 用户后端选择 `engine_mode` | 默认 `auto`；手动模式写明读取、写入、修改或转换阶段的具体后端；不存在渲染后端。手动选择的执行规则见第 6 节。 |
| 规模与资源 `workload_limits` | 记录测试覆盖的文件数、sheet 数、行列数和对象数量。用户给出最长耗时/峰值内存上限时纳入契约；没有上限时不自行设置“超过某 MB 就用 Rust”等阈值。 |

保留项按实际对象列出，至少检查以下类别：公式和缓存、合并、字体/填充/边框/数值格式、行高列宽/隐藏状态、工作表名/顺序/可见性、打印设置、批注文本、批注外观、定义名称、超链接、数据验证、条件格式、表格、图表/图片/形状、外部链接、VBA、ActiveX/OLE、未知扩展部件。

对象清单必须检查原始文件。xlsx/xlsm 的部件及关系不能只以 openpyxl 已加载的对象为准，因为未支持的部件不会因此变成“不存在”。未识别的部件记为“未知”，没有覆盖该部件保留要求的适配器不得保存此文件。

### 必须先拒绝的冲突

- 要求保留 VBA/XLM 宏，却指定 xlsx 输出：停止并让用户在支持宏的格式与明确丢弃宏之间选择；默认不丢弃。xlsx 不能保存 VBA/XLM 宏，xlsm 可以保存。[Microsoft 格式说明](https://learn.microsoft.com/en-us/office/compatibility/office-file-format-reference)
- 要求输出 CSV，同时保留多个工作表、单元格格式、批注或可执行公式：停止并要求调整输出契约。CSV 字段里出现“=...”文本不等于保存了工作簿公式及其计算能力。
- 要求本轮计算结果，却禁止所有满足该公式链的计算引擎：报告不支持；禁止读取旧缓存冒充重算。
- 要求保留全部源对象，但对象清单含当前适配器未支持或未识别的部件：该适配器不合格；没有合格后端时停止。
- 文件存在宏、对象或签名，而格式转换会删除或使其失效：先报告冲突。保留 VBA 二进制项目不等于执行 VBA，也不等于保留数字签名有效性。

## 3. 路由算法与“已适配”的定义

开发新功能时，先按主表的候选优先级评估在库能力，再针对格式、数据归属、输出契约和目标平台选择实现目标，然后开发适配器、补齐对应验收，达到“通过”后再交付。候选顺序不等于该功能已验收的生产路由；安装了库或 benchmark 通过都不能代替业务验收。已获授权的开发任务应完成这些工作，不能以“还没有适配器”为理由只提交选型建议。资源预算需要性能测量证明，库文档不能代替测量。

以下六步用于正式执行已开发的功能，不跳步：

1. 解析第 2 节契约，检查冲突，识别输入对象。
2. 按第 4 节匹配操作编号；先匹配特殊要求，再匹配只读值等通用行。例如需要公式文本时匹配 R03/R05，不匹配 R01。
3. 生成候选集。后端必须同时满足：已实现适配器、该操作/输入/输出/保留项/平台已有通过的验收记录、当前运行环境可加载；存在资源预算时还须满足对应规模下的预算。仅安装了库、查到官方支持或存在函数代码均不满足此条件。
4. 手动选择：仅执行用户选定且满足契约的后端。不合格或执行失败时停止并说明原因，禁止静默换引擎。
5. 自动选择：先使用满足契约的功能默认后端；该功能未设置默认或默认不可用时，按主表的默认顺序选择第一个合格后端。顺序中的后端不合格就排除；全部排除后报告不支持或缺少引擎。
6. 执行并验证输出；第 6 节规定哪些失败允许自动重试。对本轮已判定不满足契约的输出，禁止通过更换引擎隐藏差异。

能力登记用现有配置、普通字典或静态表即可，不要求新增插件框架。每个登记项至少记录：功能/操作编号、后端与版本、输入输出格式、覆盖的保留项、系统/架构、适配器入口、验收报告或测试证据、功能默认值。

能力状态只有三类：

| 状态 | 判定条件 | 自动执行 / 用户选择 |
|---|---|---|
| 通过 | 适配器已实现，且本次契约属于已通过的验收范围 | 进入候选集 |
| 未验收 | 缺少上述验收证据；包括仅有库文档、仅有 mock、仅存在代码 | 不进入候选集；开发阶段在隔离副本上补验收 |
| 不支持 | 后端缺少本次必须能力，或目标平台没有对应实现 | 不进入候选集；报告缺少的能力 |

## 4. 功能读取、写入与修改主表

表中 `A → B` 表示自动模式按顺序从**合格候选集**选择，不要求为每个功能实现所有后端。“同契约备选”必须满足第 3 节后才能展示给用户。`原生表格引擎`、`原生文字引擎` 按第 5 节解析。

| 编号 / 功能及匹配条件 | 默认读取 | 默认写入 / 修改 / 执行 | 同契约备选 | 明确边界 |
|---|---|---|---|---|
| F01 文件扫描、按文件名重命名、排序前缀、复制、移动、归档 | pathlib / os；不读取表格内容 | pathlib / shutil / os | 无需 Excel 后端选项 | 文件字节必须保持一致。文件冲突、占用和跨卷移动按功能定义处理。 |
| F02 按单元格内容重命名文件 | 存储值执行 R01；显示文字执行 R04 | 文件名修改执行 F01 | 沿用读取阶段的合格备选 | 不对工作簿调用 save；不通过重存工作簿完成文件名变更。 |
| R01 只读值、sheet names；不需要格式、批注、公式文本、原始错误类型 | Rust-owned 普通存储值 XLSX 且匹配基准契约：优先评估 Calamine；其他情况仅使用对应格式/契约已验收的 reader | 不写源文件；生成结果另匹配 W01 | 当前数据归属、格式和契约已验收的 reader | Calamine 错误必须如实报告，不能再用 Direct OOXML 掩盖；不得把失败或 Excel 错误替换成 0/空白。Python-owned 迁移期保留原项目同契约已验收路由；openpyxl 仅对拍。未覆盖格式不支持。 |
| R02 按单元格坐标读取值与合并区域 | 普通存储值仍按 R01；合并区域等字段按 Calamine 对该格式/契约的验收范围读取 | 不写源文件 | 需要 OOXML 专属结构时，仅用该对象/契约已验收的专用 reader | Calamine 返回值读取错误时不转为通用 OOXML fallback；所需字段未提供或专用适配器未验收时报告具体能力缺项，不得解释成“没有合并”。 |
| R03 读取公式文本、批注文本、样式、打印设置或名称 | 公式/值字段使用对应格式已验收的 Calamine 能力；OOXML 专属字段单独走对应对象已验收的 namespace-aware reader | 不写源文件 | 覆盖本次所需部件的已验收 Rust reader | OOXML 补读只补明确请求且缺失的字段，不掩盖底层值读取失败；未实现的对象读取标为“未验证”，不得伪造；区分文本“#N/A”和 Excel 错误时保留原始类型。 |

### 主表附加硬条件

- Calamine 需要保持源单元格坐标时使用 `skip_empty_area=False`，或由适配器正确回补源区域起点；不允许直接丢掉前导空行列。
- openpyxl 只读值的模式与可编辑模式分别登记；`read_only=True` 不用于修改，`write_only=True` 不用于编辑已有文件。
- openpyxl 不负责自动维护插入/删除行列后的全部依赖；W04 必须使用表中单独的依赖条件。[openpyxl 结构编辑说明](https://openpyxl.readthedocs.io/en/stable/editing_worksheets.html)
- openpyxl 的批注读写覆盖文本，批注格式和读取时的尺寸不在默认保留范围；需要保留外观的任务不能选普通批注适配器。[批注说明](https://openpyxl.readthedocs.io/en/stable/comments.html)
- 对不在 `preserve` 中的源版式，可以不复制；对必须保留而后端未覆盖的对象，排除后端。禁止以“多数场景可用”绕过该判定。

## 5. 外部引擎边界

本项目的 deb 不带 Office、WPS、LibreOffice、Python、COM 或 UNO。普通功能不依赖这些运行时；公式重算和同类格式转换仅在用户显式触发时经独立 sidecar 调用。sidecar 缺失时报告“该功能需要外部引擎”。PDF、渲染和跨类别转换不在范围内。保留 VBA 项目不代表运行 VBA。

## 6. 多后端用户选择、失败与回退

### 用户选择

- 只有一个合格后端：直接运行，界面不要求用户选技术。
- 同一阶段存在两个以上合格后端：提供“自动（默认）”和各后端名称，允许用户选择。选择范围按功能和读取/写入/修改/转换阶段设置，不提供无能力区别的全局技术菜单。
- Rust workspace 直接使用 calamine crate；旧 pandas/calamine engine 只属于 Python 对拍背景，不引入生产依赖，也不作为产品里的后端选项。
- 每个选项说明其保留范围、是否启动外部应用、已记录的性能与环境依赖。只允许同一契约的技术互换；“按值复制”和“保留格式复制”属于不同输出模式，不能混在技术选择中。
- 未实现、未验收或本机不可用的技术不进入可执行选项；已持久化的手动选择失效时，保留设置并提示用户处理，禁止静默切换。
- 持久化范围至少包含功能、阶段、输入输出格式和系统；同一平台的架构差异通过能力筛选处理。
- 用户未调整设置时使用自动默认，不在每次启动和每个文件上重复提问。

### 失败与回退

R01/R02 的普通值读取不适用通用“切换下一 reader”回退：Calamine 的读取错误不能靠 Direct OOXML 重试来掩盖。需要 Calamine 未提供的 OOXML 专属字段时，应为该字段匹配已验收的专用 reader；缺少时报告能力缺项。其他允许回退的读写阶段仍须遵守下表、从原始输入或干净副本开始，并满足完整契约。

| 情况 | 自动模式行为 | 手动模式行为 |
|---|---|---|
| 执行前发现未安装/无法加载引擎，或缺少已声明能力 | 对允许回退的操作排除该候选，按第 4/5 节顺序选择下一个合格候选；R01/R02 普通值读取遵循上方特例 | 停止并报告用户选定引擎不可用 |
| 适配器明确报告格式/特性不支持，且另一候选覆盖全部要求 | 从原始输入或干净副本重试下一合格候选，并记录原因 | 停止，展示满足条件的其他选项 |
| 文件损坏、密码/加密未处理、权限、输入/输出被占用、磁盘空间不足 | 停止当前任务并报告原因；不更换引擎掩盖问题 | 同左 |
| 输出校验差异、计算错误、缓存未刷新、超时或未知异常 | 停止，保留诊断和临时输出；不自动回退 | 同左 |

每次输出先写临时文件，通过契约验证后才提交到最终路径。覆盖用户文件必须遵循功能已有授权和备份策略。禁止对半写入结果继续回退。禁止用 `except Exception` 把所有错误归为兼容失败。

运行日志记录功能/操作编号、输入输出格式、实际后端与版本、选择原因、回退原因、读取/计算/写入耗时、失败类别和未满足的保留项。

## 9. 验收、效率与切换默认值

本节补充验收项目；测试与发布仍执行 [rules/07](07_测试与发布.md)，并遵守本文件和 [AGENTS.md](../AGENTS.md) 的迁移顺序。不得因某个适配器只覆盖一个操作而缩减保留项验收。

### 能力验收

同一适配器按“操作 + 格式 + 保留项 + 系统/架构 + 依赖版本范围”记录证据；未执行项写“未执行”。

- 读取对拍：单元格坐标、字段/列序、前导空区、空白/零、文本代码、日期与 1900/1904 日期系统、错误类型和所选公式口径。
- 写入对拍：本次输入输出契约中每个保留项；修改既有文件时同时检查未修改区域和其他 sheet。
- W04 结构修改必须覆盖受影响公式、定义名称、跨表引用、表格/图表引用和打印名称；发现未知依赖时不能登记该对象组合通过。
- 公式重算旁路按本文件专项要求验收缓存刷新；缺少 sidecar 时主路径报告外部引擎缺失且其他功能照常运行。
- 输出须通过结构检查和独立 reader 重开；openpyxl 仅作对拍基线。由于目标机上不安装 Office/WPS/LibreOffice，无法宣称应用渲染、宏行为或原生打印验收通过；遇到未覆盖对象时拒绝处理。
- 只读输入执行前后 SHA-256 必须相同；授权原地修改的文件先保留输入副本和哈希，最终文件验证预定变更及其余保留项。xlsx 输出比较值和对象语义，不要求整个 ZIP 字节相同。

### 性能与迁移

分别记录读取、业务计算、写入、应用启动/重算/保存和完整流程时间，同时记录峰值内存与输出大小。同机、同输入、同契约预热后至少五次，报告中位数和范围；写入基准使用同一预生成结果，Rust 测量包含桥接成本。ZIP 压缩设置相同的对比和实际交付设置的对比分别记录。

为性能原因切换已有默认值前，必须在任务中确定最小节省秒数、最小加速比例、内存上限和测试规模，并用结果逐项判断。未给出这些指标时保留现有默认，提交测量结果供用户选择；不以“更快”“收益明显”“文件很大”作为切换条件。

为新增格式/修复兼容问题切换后端时，以原缺陷复现、目标契约通过和受影响回归通过作为切换条件，不要求虚构性能收益。新功能无历史默认时按第 4 节顺序设置首个合格后端。

## 10. 本项目选型实例

1. Rust-owned 的 xlsx/xlsm 普通存储值和公式字段：按对应格式/契约已验收的 Calamine 能力读取；Calamine 错误不回退到 Direct OOXML。只对明确需要且 Calamine 未提供的批注、样式等 OOXML 字段使用该对象已验收的 namespace-aware reader。openpyxl 只在 tests/compare 作对拍；Python-owned 迁移期数据流保留原项目已验收的同契约路由。
2. Rust-owned 结果新建纯数据 xlsx：优先评估 rust_xlsxwriter，只有输出契约和功能级内存预算均通过才采用。基准中的 Direct OOXML 写入来自 Python S5/S2 专用 writer，不是 Rust 实现；Rust Direct OOXML 候选须有明确专用契约/OOXML 对象要求或同契约实测资源收益，并独立验收。不得用新建 writer 修改既有文件。
3. 修改现有模板：业务生成 ExcelEditPlan，ExcelModifier 按本次对象清单和操作批次选择一个已验收引擎。不得将同一批修改连续交给多个引擎；失败后从原始文件重新执行备选方案。遇到未验证对象时停止。
4. 公式重算默认关闭；显式重算及同类格式转换只通过 sidecar/lo-convert。PDF 导出、渲染和跨类别转换不支持。

## 11. 技术事实与参考资料

- Rust calamine crate 是生产 reader；python-calamine 的 stub 只可帮助理解旧 Python 基线，不能作为 Rust API 或能力证据。按 workspace 锁定的 calamine crate 版本逐项验证合并区域、坐标与空区行为，库升级不能自动扩大项目验收范围。
- pandas 的 Excel engine 与 xlrd 2.x（仅 xls）是旧 Python 环境参考；本迁移项目不部署或调用这些 Python 库，Excel 读取按 R01–R05 的 Rust 能力和验收范围执行：[pandas IO](https://pandas.pydata.org/docs/user_guide/io.html#excel-files)、[xlrd](https://xlrd.readthedocs.io/en/latest/)。
- openpyxl 不计算公式；单工作簿 copy_worksheet 不提供跨工作簿完整复制：[教程](https://openpyxl.readthedocs.io/en/stable/tutorial.html)、[公式](https://openpyxl.readthedocs.io/en/stable/simple_formulae.html)、[结构修改依赖](https://openpyxl.readthedocs.io/en/stable/editing_worksheets.html)、[批注](https://openpyxl.readthedocs.io/en/stable/comments.html)。
- Direct OOXML 是 ZIP/XML 访问方式，不是具体库。写入适配器必须使用 namespace-aware XML parser，维护关系、Content Types、sheet 身份/顺序、共享字符串和名称引用；不以正则替换 XML 全文实现通用结构修改。
- rust_xlsxwriter 创建新工作簿，不读取或编辑已有文件；umya-spreadsheet 必须有本项目桥接适配器和对应对象验收才进入候选：[rust_xlsxwriter](https://docs.rs/rust_xlsxwriter/latest/rust_xlsxwriter/workbook/struct.Workbook.html)、[umya](https://github.com/mathnya/umya-spreadsheet)。
- LibreOffice 与 Excel 的转换、公式和对象语义存在差异；该事实落实为具体契约验收和能力排除，不能写成“默认等价”：[LibreOffice 兼容说明](https://help.libreoffice.org/latest/en-US/text/shared/guide/ms_import_export_limitations.html)。
- ET/ETT 与标准 Excel 文件分别处理：[WPS ET](https://www.wps.com/feature/et-file/)、[WPS ETT](https://www.wps.com/blog/how-to-open-convert-and-create-ett-file/)。
- 宏格式与 COM 位数边界：[Microsoft 文件格式](https://learn.microsoft.com/en-us/office/compatibility/office-file-format-reference)、[Microsoft 进程互操作](https://learn.microsoft.com/en-us/windows/win32/winprog64/process-interoperability)。
- 项目约束入口：[workspace AGENTS.md](../../AGENTS.md) 与 [Audit AGENTS.md](../AGENTS.md)；文件硬边界：[rules/03](03_Excel与OOXML边界.md)；测试与迁移：[rules/07](07_测试与发布.md)；修改记录：[rules/08](08_AI协作与修改记录.md)；rules/11 仅记录旧产品版本体系，不用于 workspace 版本治理。
