# 核心架构与跨平台补充

> 本规则迁移自 Open-Data-Audit 的旧 Python 工程。旧目录、运行时和 Office 调用只描述来源实现；当前 Rust workspace 的目录与技术边界以根 `AGENTS.md` 为准。

## Workspace 实现边界

- Audit 业务逻辑、配置解析和审核流程迁移到 `audit-core/`；Excel 原语放在 `crates/` 下的共享库。`audit-core` 不依赖 `pytools-core`。
- 生产主路径使用 Rust，不运行 Python。Python 仅可用于旧项目对拍基线和测试辅助。
- 平台差异不得散落在业务规则中。公式计算属于独立 `ExcelCalculator`：用户显式请求且对应能力通过验收后，可选择 LibreOffice Calc（Windows/Linux）或 Windows Excel/WPS COM；同类格式转换仍由用户显式触发并经独立 `sidecar/lo-convert` 调用。外部引擎缺失或失败不得阻断其他主路径功能。
- 读取继续以 Rust `calamine` 为主，新建继续以 Rust `rust_xlsxwriter` 为主；常规修改与打印页面设置不依赖 Office/WPS/LibreOffice/COM/UNO。未来 Windows COM 修改仅可由 `ExcelModifier` 显式选择已验收的 Microsoft Excel COM 或 WPS COM 后端执行，不得从业务代码直接启动 COM。Linux 不依赖 COM。打印只写页面设置，不渲染、不导出 PDF。
- Windows 仅作为当前开发和对拍环境；交付目标为麒麟 V10、统信 UOS V20 x86_64，glibc 符号版本不高于 2.28。目标平台验收遵循根 `AGENTS.md` 和 rules/07。

## 源项目平台行为的迁移处理

- 旧项目 Windows Excel/WPS COM 与 UOS/Linux Python/LibreOffice 分支仍是业务行为发现材料；它们不自动成为后端。生产 COM 仅限经 `ExcelModifier` 能力路由验收的 Windows 修改，以及经 `ExcelCalculator` 验收的 Windows 计算；LibreOffice 仅作为显式选择并验收的计算后端或已批准的转换引擎。
- 如旧流程包含公式复制、模板操作或计算，应拆分为公式文本处理、静态工作簿修改和可选公式重算，再分别按 workspace Excel 契约选择实现。
- 被批准的公式计算与同类格式转换通过各自独立适配器/sidecar；Windows COM 修改只能经 `ExcelModifier` 显式路由至通过验收的后端。其余旧平台专属步骤须在 Rust 主路径实现、明确标为未支持，或作为待确认项；不得默认保留旧 COM/UNO 业务工作流。
- 平台相关变更按操作契约做对拍；未实际运行的目标平台或外部引擎必须标记“未执行”，不能宣称通过。
