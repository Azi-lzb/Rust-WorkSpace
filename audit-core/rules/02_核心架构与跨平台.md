# 核心架构与跨平台补充

> 本规则迁移自 Open-Data-Audit 的旧 Python 工程。旧目录、运行时和 Office 调用只描述来源实现；当前 Rust workspace 的目录与技术边界以根 `AGENTS.md` 为准。

## Workspace 实现边界

- Audit 业务逻辑、配置解析和审核流程迁移到 `audit-core/`；Excel 原语放在 `crates/` 下的共享库。`audit-core` 不依赖 `pytools-core`。
- 生产主路径使用 Rust，不运行 Python。Python 仅可用于旧项目对拍基线和测试辅助。
- 平台差异不得散落在业务规则中。公式重算和同类格式转换如经用户显式触发，才可通过独立 `sidecar/lo-convert` 进程调用已安装的 LO/COM；旁路缺失或失败不得阻断其他主路径功能。
- 其他 Excel 读取、计算、修改和打印页面设置不得引入 Office/WPS/LibreOffice/COM/UNO 依赖。打印只写页面设置，不渲染、不导出 PDF。
- Windows 仅作为当前开发和对拍环境；交付目标为麒麟 V10、统信 UOS V20 x86_64，glibc 符号版本不高于 2.28。目标平台验收遵循根 `AGENTS.md` 和 rules/07。

## 源项目平台行为的迁移处理

- 旧项目 Windows Excel/WPS COM 与 UOS/Linux Python/LibreOffice 分支是行为发现材料，不是 workspace 的后端选择规则。
- 如旧流程包含公式复制、模板操作或计算，应拆分为公式文本处理、静态工作簿修改和可选公式重算，再分别按 workspace Excel 契约选择实现。
- 只有被批准的公式重算和同类格式转换可调用 sidecar；其余旧平台专属步骤须在 Rust 主路径实现、明确标为未支持，或作为待确认项，不得默认保留 COM/UNO 调用。
- 平台相关变更按操作契约做对拍；未实际运行的目标平台或外部引擎必须标记“未执行”，不能宣称通过。
