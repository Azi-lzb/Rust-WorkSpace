# 测试、验收与发布规则

> 本文件迁移自 Open-Data-Audit。旧 pytest/S1/S2/S3/S5 测试分组只用于定位 Python 基线；workspace 的 Rust 测试和 Excel 能力验收遵循根 AGENTS.md、[根规则 13](../../rules/13_Rust_Excel读写修改与引擎路由规范.md) 及本节的业务证据要求。Python 测试脚本仅为基线/辅助；唯一生产 Python 例外是 workspace 根规则 13 的隔离 openpyxl 修改 worker。

测试范围以 `AGENTS.md` 的功能变更要求为入口；本文件规定验证层级和报告证据。

## 测试选择

- 每次新增/修改 Rust 功能，先跑对应 crate 的定向 `cargo test`，再跑受影响 workspace 测试；业务功能还须按迁移清单执行 Python 基线对拍。跨 crate 改动覆盖所有受影响 crate。
- 发布候选运行 workspace 全量测试和目标打包检查；只改文档时不要求运行 Rust 测试。Python 测试脚本只作基线或测试辅助；若产品启用隔离 openpyxl worker，还须验收内置 runtime、worker 协议、GLIBC 依赖和目标平台，不得依赖系统 Python。
- 按风险追加：脱敏/合成 fixture、文件结构与独立 reader 重开、Python/openpyxl 对拍、VBA/黄金业务基线对拍。Office/LO 只用于经授权的 sidecar 公式重算或同类转换验收；不做打印/PDF 渲染验收。目标平台或旁路未执行时注明“未执行”。
- Sidecar 路径不得只靠 mock 宣布通过；旁路输出必须校验，未安装旁路时验证主路径可用且正确报告外部引擎缺失。
- 读取 Audit 现有配置时，使用 `audit-core/config-real/` 中已脱敏且本地保留的数据；缺失项才可使用公开占位配置。配置和真实工作簿均只读，修改场景先复制到临时目录，并记录实际配置来源。Rust 测试不得依赖旧 `core/tests/config_paths.py`。

## 必要证据

- 业务输出：相同输入和配置下，核对文件数量、数据数量、关键值与审核结论；日志/性能开关不得改变业务结果。
- 原始文件：重要流程执行前后比较 SHA-256，证明输入未被修改。
- 工作簿：验证预期公式、格式和结构；OOXML Patch 结果须通过包关系校验和独立 Rust reader 重开，Python/openpyxl 可作额外对拍。
- VBA/规则迁移：核对数量、启用规则存活率和触发行为；数量差异必须逐项解释，不能以“基本一致”代替。

## 报告格式

说明实际执行的命令/范围，并报告 `passed / skipped / failed / errors` 数量；列明新增或未新增测试的理由、真实数据验收结果及未执行的平台专属项目。不得把未执行写成通过。

## 性能优化

性能优化还要证明业务结果和文件结构未变。测量项以 `rules/09_技术实现参考.md` 的性能清单为准，至少保留输入规模、关键阶段耗时、输出差异和公式错误信息。
