# UI 与接口规则

> 本规则迁移自旧产品 UI。当前 workspace 尚以 Rust 业务和 CLI/库迁移为主；只有实际纳入产品的 UI/桥接接口才应用具体视觉细节。旧 Python shell 路径不作为新架构要求，后端实现须遵循根 `AGENTS.md`。

## 前后端边界

- 前端调用统一桥接 API；迁移后的业务实现位于 `audit-core/` 或共享 `crates/`，不把旧 `core/` 路径复制进本 workspace。
- 不因本规则保留 `shell-flask/`、`shell-pywebview/` 或 Python 运行时；如未来增加前端，必须另行确定 Rust 侧接口和打包边界。
- 后端新增前端接口时，应同步接口说明/约定。
- 工作台命令栏只能调用工具内置动作，禁止把用户输入直接交给 shell。

## 设置页视觉与交互

以下约定仅在后续产品实际包含设置 UI 时适用：

- 每项一行；左侧名称和简短说明，右侧控件。
- 是/否用 toggle；多选一用下拉框；相关项进入分组卡片。
- 说明写用户效果，不写底层实现细节。
- UI 默认显示文件名，不展示长绝对路径；全路径放 tooltip；打开路径必须调用受控 API。
- 左侧主导航；每个业务系统独立页面；执行按钮归属对应系统页面；运行记录/日志可以全局共享。

## 用户错误与技术日志

用户提示必须回答：
1. 哪个文件/工作表/规则出了问题；
2. 用户能理解的原因；
3. 下一步怎么处理。

技术日志才记录：
- Rust 错误链和诊断信息；
- 用户显式触发 sidecar 时产生的 LO/COM 诊断信息；
- rId/Relationship/part/Target、内部错误码、源 XML 和原始异常。

不要把底层异常原样当作主要用户提示。
