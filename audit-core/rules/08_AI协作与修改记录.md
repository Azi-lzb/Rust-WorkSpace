# AI 协作与修改记录

委派原则见 `AGENTS.md`。本文件补充 WIP 保护和记录格式。

## WIP 保护

修改前查看当前 commit、`git status` 和未提交文件。不得用旧文件整份覆盖用户 WIP；按修改意图最小化合并。子 Agent 只能在分配范围内工作，不得 commit、push、merge、rebase 或创建 PR。

## GPT 修改记录

实际修改项目文件后，在 `GPT修改记录/YYYYMMDD_HHMMSS_修改总结.txt` 新增记录，不覆盖旧记录。至少填写：

- 时间、执行者、修改前/后 commit（可取得时）及 WIP 情况；
- 修改目的和修改/新增/删除文件；
- 逻辑或文档变化、配置及 VBA 迁移影响；
- 实际测试结果、未执行项、已知问题；
- 删除清单和回滚提示；
- 业务功能/配置变更时的【组件版本】字段；纯文档/治理变更写“不升级”。

记录本身不递归生成新记录，默认纳入版本控制。子 Agent 汇报应精简到改动文件、关键设计/风险、命令与结果、未完成事项；主 Agent 仍需检查 diff 并整合验收。
