# VBA 行为迁移与配置复核

本规则描述 Audit 的业务迁移和配置执行性约束，必须与 workspace 根 AGENTS.md 的技术边界共同执行。它不覆盖 Rust/Go/OOXML 后端、Python 生产路径或 sidecar 白名单。

## 行为基线

旧 VBA 工作簿是迁移阶段的业务行为基线之一。

迁移后的 Rust 业务层可以：
- 合并 Sheet；
- 拆分 Sheet；
- 重命名配置；
- 重构执行模型。

但每类正式 VBA 业务能力必须对应明确的：
1. 配置/数据模型；
2. ConfigLoader；
3. Validator / Preflight；
4. Engine；
5. Test。

判断“一比一复刻”看业务语义和执行结果，不看 Excel 外观。

## 启用规则禁止静默丢弃

恒等式：

`启用规则数 = 成功进入执行链的规则数 + 明确报告失败的规则数`

禁止：
- parse 失败后 `continue`；
- 正则非法后当成不匹配；
- 非法数值静默退默认；
- 规则注册失败后仍显示“执行成功”。

正式运行存在启用但不可执行规则时，应阻断该功能，避免生成“看似完整、实际上漏跑”的结果。

## 配置体检必须复用运行时逻辑

Validator / Preflight 应尽量复用正式：
- token parser；
- 正则 parser；
- 表达式 parser/compiler；
- 枚举；
- 数值解析。

禁止维护“检查能过、Engine不能跑”的第二套语法。

## 检查器只读

可以：
- 报配置册/Sheet/Excel 行；
- 报规则编号；
- 展示原始 token/表达式；
- 说明错误；
- 高置信时提供“建议人工改为”的候选。

禁止：
- 写回 Excel；
- 自动补逗号；
- 自动改公式/编号/阈值/启停；
- 多轮字符串 replace 后继续正式执行；
- 在内存中偷偷替用户“修好”。

所有建议必须明确：`建议人工复核，程序未自动修改配置。`

## 错误提示质量

每条失败规则至少包含：
- 配置册/Sheet；
- Excel 行号；
- 规则编号；
- 字段；
- 原始规则/token；
- 错误类型；
- 原因；
- 必要时的段数/槽位；
- 高置信候选建议。

不能只写“表达式有误”。

## 3.1 / 3.2 配置执行性

3.1 表达式和 3.2 Left/Right/校验公式都属于配置驱动执行：
- 各自使用对应正式 grammar；
- 都必须有 Preflight；
- 都必须保证启用规则“可执行或显式失败”；
- 不能把 3.1 的 8 段 token 规则错误套到 3.2 的 5 段语法上。

## 数据属性驱动

计算逻辑应按数据属性分流，不得按指标代码白名单打补丁。

例如“百分数”如果项目定义原始值 `9.92` 表示 `9.92%`：
- 跨期变化按百分点差异 `current - previous`；
- 不再套普通相对变化率；
- 不计算普通倍率；
- 不进入为普通数值设计的倍数/相对增降幅警戒。

具体业务属性语义以正式配置和用户确认口径为准。

## 3.1 表达式 8 段/5 段双轨（LEGACY_8 / FIVE_SEGMENT_V1）

3.1 执行比较存在两套**正式兼容语法**，由设置中心「3.1 表达式规则语法」
（central_expression_schema）显式切换，默认 LEGACY_8：

- **LEGACY_8**：读取「表达式校验」，token 八段
  `[业务类,机构,地区,指标,数据属性,币种,频度,批次]`，空段=继承当前行，
  机构/地区段支持 `左中/右中` 正则字符类转写（VBA 兼容）；
- **FIVE_SEGMENT_V1**：读取「表达式校验5段式」，token 五段
  `[指标,数据属性,币种,频度,批次]`；机构/地区**提升为规则级作用域列**
  （标准正则直接写，出现左中/右中为配置错误）；规则作用域=机构列正则
  ∧ 地区列正则，token 只在当前机构+地区桶内取数，**禁止跨机构笛卡尔积**。

铁律：

- 禁止按 token 段数自动猜测模式；读取哪张表完全由 schema 决定，
  禁止静默 fallback；
- FIVE_SEGMENT_V1 正式执行前必须通过 5 段取数键唯一性审计
  （机构+地区桶内同键多记录 → 明确报错阻止，8 段不受影响）；
- 5 段求值经 8 段化桥接（业务类从旧表配对 token 恢复、机构/地区置空），
  复用既有 SBE/LAE 求值器与取数键逻辑，禁止新造第二套求值器或与 3.2
  不一致的 5 段空值语义；
- 启用规则 = 可执行 + 显式失败：5 段规则无法 parse/compile/resolve
  必须明确报错，禁止静默丢失；
- 配置检查按当前 schema 体检对应工作表（8 段/5 段分区显示），
  检查器复用运行时 parser，禁止另立业务真相。
