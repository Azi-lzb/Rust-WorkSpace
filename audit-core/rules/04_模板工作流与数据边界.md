# 模板、工作流与数据边界

## 文件边界

- 迁移后的 Rust 业务代码不得写死机构名、数据期、绝对路径或具体业务公式；这些值应来自配置、输入或明确的业务常量。此约束也适用于未来获准的 Go 修改 worker。
- 原始报送文件只读；重要流程按 `rules/07_测试与发布.md` 验证执行前后 SHA-256 不变。
- 默认输出到用户选择的目录，不覆盖原始文件。
- 本机运行数据（如用户设置、模板索引）与程序版本分离。
- 用户人工填写的历史反馈/审核意见不得被程序升级覆盖。

## TemplateSnapshot

模板静态信息只提取一次，形成轻量只读 `TemplateSnapshot`。具体读取技术按 `rules/03_Excel与OOXML边界.md` 选择：
- 模板规则；
- 命名区域索引；
- 表结构期望值；
- 全部公式文本；
- 校验区域公式矩阵；
- 规则公式值。

Snapshot 不保存 Workbook、COM Workbook、UNO 文档或文件句柄。

TemplateSnapshot 只包含业务所需的不可变数据，不保留底层 reader、Workbook、sidecar 文档或文件句柄。不得为复刻旧 Windows `Range.Copy` 而在主路径额外启动 COM。

## 模板与命名区域

新式模板的业务定位应依赖稳定规则编号和命名区域，不得把定位逻辑写死在 Rust/Go 代码中。

旧 VBA 批注协议只作为未迁移模板的临时兼容。

外部辅助文件：
- 优先从模板公式识别实际引用工作表；
- 无法识别动态引用时才回退复制全部工作表；
- 与报送文件同名的待复制 Sheet 必须明确失败，不覆盖、不自动改名。

## 汇总核查 DAG（核心顺序）

1. 报送文件来源
2. 模板装载与体检
3. 命名区域检查
4. 表结构比对
5. 条件格式结果提取
6. 复制审核副本
7. 外部文件添加
8. 公式校验复制
9. 工作簿真实计算
10. 校验结果提取
11. 问题汇聚
12. 历史说明富化
13. 结果输出
14. 运行日志输出

公式复制/写入与公式重算是不同能力。主路径保留公式文本；只有用户显式要求本轮计算结果时，才以 sidecar 执行重算。不得因旧平台曾合并执行而默认启动 Office/LO。

## 表结构比对

这是批量热路径：
- 模板静态期望值尽量一次读取；
- 报送文件使用已验收的纯 Rust reader（默认 Calamine），其内存与坐标行为按实际工作簿规模测量；
- 不为结构比对启动 Excel；
- 不在热循环做无必要正则或复杂标准化。

## 组合与联合模板

- 组合工作表属于文件/值处理，不需要公式计算引擎。
- 制作联合模板复用模板协议；各平台如存在实现差异，业务语义和对拍结果必须一致。Windows 开发机行为不能替代麒麟/UOS 目标平台验收。
